The click handler's new branch is exercised by every pre-existing click test (20 `dom-click` rows, the README GUARD row, both divide-by-zero suites) and all are green; a click on a gap in the button grid still does nothing and does not throw (B6); the blur is now strictly *less* aggressive than the reviewed-green cycle-1 code for clicks, and identical for pointer clicks. `index.html` and `style.css` untouched, classic scripts only, no dependency added, so the `file://` promise is unaffected.
- **Conventions & complexity**: conforms to CLAUDE.md §4 — 2-space indent, single quotes, semicolons, `const`/`let`, `camelCase`, `UPPER_SNAKE` (`KEY_MAP`), behavioral test names, comments that explain *why* (the new comment block at `script.js:74-79` explains the `detail` rationale and cites D-011). The fix adds one integer comparison per click. `KEY_MAP` is built once (~25 entries) at load. Examined: the keydown path, the click handler, `dispatch`/`updateDisplay`, `KEY_MAP` construction. Nothing grows with input length except `history`, untouched by this unit.
- **Architecture fit**: the fix follows D-011's lasting rule — focus policy is read from the event's reported origin, not inferred from adapter-held state — and adds no mutable binding, honoring D-005 clause 2.
